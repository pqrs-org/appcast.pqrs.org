- 🔔 Important Notes
    - After upgrading, enable `Karabiner-Elements Privileged Daemons v3` under Background App Activity in System Settings.
- 💥 Breaking Changes
    - Moved `karabiner_cli` from `/Library/Application Support/org.pqrs/Karabiner-Elements/bin/karabiner_cli` to `/Applications/Karabiner-Elements.app/Contents/Helpers/karabiner_cli`.
    - Moved bundled helper apps into `/Applications/Karabiner-Elements.app/Contents/Helpers`.
    - Moved maintenance scripts into `/Applications/Karabiner-Elements.app/Contents/Resources`.
- ✨ New Features
    - Added Japanese localization.
    - Add Simplified Chinese (zh-Hans) translations (Thanks to @maodun96 and @msuadOf)
    - Added [`mouse_motion_and_wheel_to_key`](https://karabiner-elements.pqrs.org/docs/json/complex-modifications-manipulator-definition/other-types/mouse-motion-and-wheel-to-key/) (Thanks to @BenjaminVanRyseghem)
    - Added [`set_caps_lock_led`](https://karabiner-elements.pqrs.org/docs/json/complex-modifications-manipulator-definition/to/set-caps-lock-led/) to complex modifications, which allows the caps lock LED to be turned on or off independently of the caps lock state. (Thanks to @anandghegde)
    - Added support for remapping buttons on supported Logitech HID++ devices. (Thanks to @robertn702)
    - Added "Shift + keys" category to Simple Modifications. (Thanks to @sadoiadosoias)
    - Added `system.ui_language` to variables.
    - Added settings to the Expert tab for including `device_address`, `location_id`, `serial_number`, and `transport` in device identifiers, allowing devices with the same vendor ID and product ID to be configured separately.
    - Added `serial_number` and `transport` support to device conditions. `device_address` conditions now use the physical device property regardless of the device identifier settings.
    - Added Accessibility monitoring settings to the Expert tab, allowing monitoring of the frontmost application, focused window, and focused UI element to be enabled or disabled independently.
- 🐛 Bug Fixes
    - Fixed an issue where Caps Lock events generated by key remapping were remapped again when CGEventTap fallback was enabled.
    - Fixed an issue where ISO layout-specific keys (e.g., `` `~ `` / `§±` / `^°` / `²` ↔ `\|` / `<>`, depending on the layout) could produce the wrong characters when CGEventTap fallback was enabled.
- ⚡️ Improvements
    - Improved text and other UI elements for macOS 27.
    - Improved focused UI element detection in Google Chrome and Electron-based applications by handling delayed Accessibility initialization. (Thanks to @duanyutong)
    - Added markers for enabled rules in the Complex Modifications assets list. (Thanks to @dhffdh)
    - Improved same-timestamp event reordering for QMK/ZMK keyboards. Modifier releases in the same HID report are now processed before key presses, and events are reordered independently for each device. (Thanks to @Leandros)
    - Changed inter-process communication between Karabiner-Elements processes from UNIX domain sockets to XPC.
    - Fixed an issue where selection indicators in the Simple Modifications key picker were not displayed on macOS 27.
    - EventViewer now displays caps lock LED state changes with an appropriate name instead of "Unsupported HID usage".
    - Add `Show confirmation submenu for Quit Karabiner-Elements` configuration.
    - JavaScript-based Complex Modifications rules are no longer evaluated while disabled.
    - Limited the maximum size of `karabiner.json` to 64 MB.
    - Limited JavaScript `console.log` output to 1 MB.
    - Improved internal handling of expressions used by `set_variable` to ensure consistent equality and hashing. (Thanks to @monsterlag)
    - Improved key repeat for mappings with modifiers so that the modifiers remain active while the key is repeating.
    - Improved `to_if_alone` handling so that actual remapped output cancels it, while keys disabled with `vk_none` do not.
    - Migrated the app icons to the Icon Composer format, and removed the app icon selection setting.
